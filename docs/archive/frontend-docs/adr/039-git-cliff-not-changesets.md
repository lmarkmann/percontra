# ADR 039: git-cliff for the Changelog, Not Changesets

**Status:** Accepted
**Date:** 2026-08-25
**Deciders:** Luis Markmann

## Context

The JS default for release notes is Changesets: a changeset file per pull request, a version bump in `package.json`, a publish step. That shape assumes consumers. This repo is `private: true`, publishes nothing, and is cloned and renamed rather than installed. A `.changeset/` directory here would be per-PR paperwork feeding a publish that never happens.

The repo already produces the input a generator needs. Commits are conventional (`feat:`, `fix:`, `chore:`, `refactor:`, `docs:`) by house rule, and `docs/TODO.md` already owns open work, so the missing half is a record of what shipped.

The target heading shape is the one used in ouroboros: `## <version> - <YYYY-MM-DD>: <headline>`. Version and date are derivable from a tag. The headline is prose and is not.

## Decision

Generate `docs/CHANGELOG.md` with **git-cliff**, configured in `cliff.toml`, driven by `just changelog`, `just unreleased`, and `just release`. Installed from npm (`git-cliff` ships prebuilt platform binaries), pinned in `devDependencies`, so a clone needs no Rust toolchain.

Three rules make the shape work:

1. **The annotated tag message is the headline.** git-cliff exposes it as `message` in the release context, and the template renders its first line after the date. `just release VERSION HEADLINE` writes the section, commits it, and annotates the tag with the same string, so the headline is typed once.
2. **A release with no version renders nothing.** The body template is wrapped in `{% if version %}`, so unreleased commits never reach the file. `docs/CHANGELOG.md` is what shipped and `docs/TODO.md` is what has not; they do not overlap. `just unreleased` supplies a version with `--bump` to preview.
3. **The changelog starts at `v0.0.0`.** That annotated baseline tag sits on the last commit before this decision. `changelog_baseline` in the justfile is the range floor. History before it is recorded in `docs/synthesis/` and is deliberately not backfilled.

`.github/workflows/release.yml` fires on a `v*` tag, checks the file carries a section for that tag, and publishes the GitHub release with `git-cliff --latest --strip all` as the body. The release body is re-derived from commits rather than sliced out of the file, so the two cannot disagree.

CI takes git-cliff as its pinned release binary, checksum-verified, the way `workflows-lint.yml` already installs actionlint and zizmor, and reads the version out of `package.json` so the local devDependency and the workflow stay one pin. That is why the devDependency is an exact version rather than a caret range. The alternative, checking out with pnpm and a Node dependency cache, is the cache-poisoning shape zizmor flags on a tag-push job that publishes an artifact.

The default `<!-- generated by git-cliff -->` footer is overridden to empty, per the repo-wide rule that nothing emitted on our behalf carries a generator marker.

## Consequences

- Cutting a release is one command and pushing stays manual: `just release 0.1.0 "headline"` then `git push --follow-tags`.
- A tag cut by hand gets no changelog section, and the release workflow fails on it by name rather than publishing an empty body.
- A commit type no parser claims lands in **Other** rather than inventing a section named after the type. Non-conventional commits are dropped entirely (`filter_unconventional`).
- `chore(release):` commits are skipped by a parser, so the bookkeeping commit that writes the file does not appear inside the section it wrote. This also keeps the local and CI renders identical.
- `package.json#version` is bumped by the same recipe. The tag is the version of record; the manifest field would otherwise sit at `0.0.0` forever and drift.
- knip resolves `git-cliff` through `cliff.toml` on its own, so no `ignoreDependencies` entry is needed.
- git-cliff writes sections, not prose. Section bodies are commit subjects; the narrative that a hand-written changelog carries lives in the headline and in the ADRs.

## Evidence

Changesets was declined, not overlooked: it is the right tool for a published package with independently versioned consumers, and this template has neither. release-plz was likewise declined; it is the Rust publish path and carries cargo release mechanics that do not apply.
