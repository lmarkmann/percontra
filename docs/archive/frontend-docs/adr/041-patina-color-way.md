# ADR 041: Patina as the Color Way

**Status:** Accepted
**Date:** 2026-08-31
**Deciders:** Luis Markmann

## Context

The template had no recorded color decision. `--primary` was `oklch(0.42 0.1 55)`, a brown, chosen without an argument anyone could inspect or retire; the only trace was `--accent-hue: 55` and a line in `token-audit.md` calling it "warm bronze". A rule whose reason is lost is a rule nobody can retire, and this was worse: a value whose reason was never written down.

The brown was not a matter of taste. At L 0.42 the sRGB gamut caps chroma at 0.104 for hue 55 and the ramp already used 0.10, so 96% of the available chroma was spent. Hue 55 belongs to the amber family, whose chroma peaks near L 0.75; anchoring it at L 0.42 lands in the region where orange is brown. No retune reconciles a hue with an anchor lightness that disagrees with it. Either the hue moves or the anchor does.

Auditing the palette to make that argument surfaced three defects the naive contrast check had never shown, because it pairs every `*-foreground` against `--background` rather than the surface a component renders on:

- `text-warning` on `bg-muted` measured 2.70:1, failing body text, large text, and the 3:1 non-text bar. `StatusPill status="warning"` was unreadable by spec.
- `text-destructive` on `bg-muted` measured 4.36:1, failing body text.
- `hover:bg-primary/80` blended the fill toward the background, so the primary button's label dropped from 6.11:1 at rest to 3.96:1 on hover. Interaction is supposed to raise contrast, not lower it.

Alongside those, 37 declared color tokens had no consumer: both primitive ramps, all five `--chart-*`, all eight `--sidebar-*`, and `--accent` / `--accent-foreground`. `--accent` (shadcn's neutral hover token) and `--accent-500` (the brand ramp) also collided under one word with two meanings.

## Decision

Adopt **Patina**, the author's published editor theme, as the template's color way. Light is Patina Stellar's ground carrying Patina Light's ink and accents; dark is Patina Dark Soft. Values are read from `palette/*.toml` in `lmarkmann/patina-theme`, which is generated by that repo's `tools/generate.py` and is the upstream for any future retune.

This makes the template a two-hue system: neutrals warm at hue 80 to 115 at the light end and achromatic at the dark end, accent verdigris at hue 161 to 167.

- **`--accent-hue` is gone.** Patina's neutrals are warm where Patina is warm and achromatic where Patina is achromatic, so no single hue variable describes them. A fork retints by regenerating, not by editing one number. This gives up the template's nicest affordance and it is the honest trade: the variable also forced chroma to stay gamut-safe at every hue, which capped it near 0.10 and was a large part of why the old accent read timid.
- **The verdigris ramp is not generated.** Each of the six `--brand-*` steps is the `accent` or `accent_hover` of a shipped Patina variant, so the scale is the theme's own rather than an even interpolation through colors Patina never had.
- **The ramp is renamed `--brand-*`,** which ends the `--accent` / `--accent-500` collision without deleting the shadcn contract token.
- **Semantic tokens reference the ramps** rather than re-typing an identical `oklch` triple, which is what makes the primitive layer load-bearing instead of decorative.
- **`--sidebar-*` and `--chart-*` are deleted.** No sidebar and no chart exist; `shadcn add sidebar` re-adds them.
- **`--primary-hover` is a real token,** because a hover expressed as an alpha fade cannot darken on a light ground.
- **Lightness is set by the worst surface a token renders on,** `--card` and not `--background`.

That last point is the one place this deviates from Patina, and it deviates by very little: three lightness nudges, the largest 0.021. Patina's README states that Dark Soft "intentionally softens a handful of tokens slightly below strict AA for reduced eye strain." That rationale is sound for an editor, where the reader chooses the theme and stares at it for hours. It does not transfer to a product UI, where AA is a compliance floor the visitor never opted into and an elevated card sits behind body text on every route. Where the two disagree, the gate wins.

## Consequences

- Every rendered text pair clears WCAG AA in both themes, and the three defects above are fixed. The numbers, and the commands that produced them, are in `docs/frontend/color-report.md`; that file is the thing to recheck after any future theme change.
- Token count drops by 13 declarations per theme. CSS goes 15.74 kB to 15.88 kB brotli: the deleted tokens were generating almost no utilities, so the two contrast-mode override layers slightly outweigh them.
- `vite/plugins/theme-fallback.test.ts` gains a `var()` resolver, since string equality would now reject `var(--gray-50)` against the identical literal in the 404 mirror. It also gained a second test: `#f5f2ed` / `#1a1a1a` appear in `index.html`'s `theme-color` metas, its boot script, and `theme-provider.tsx`, none of which can be a CSS variable, so the test converts `--background` to hex and asserts all three copies against it. Those four copies previously had no guard at all, while `404.html` did.
- The template ships a color identity rather than a placeholder, which is a change in kind: a fork now overrides an argued choice instead of filling in a blank. `.claude/rules/bootstrap-new-project.md` still lists the color way as fork work, and that stays true.
- Patina is MIT and authored by the same person, so vendoring its values carries no license or drift risk beyond remembering that `palette/*.toml` is upstream.
- `forced-colors: active` and `prefers-contrast: more` ship as override layers on these same semantic keys. Emulating forced-colors found two Major defects that predate this ADR and that no contrast calculator can see, because the UA replaces the palette: the focus ring is a `box-shadow` (`ring-3`) on buttons that also set `outline-none`, and the card boundary is a `0 0 0 1px` `box-shadow`. This mode drops `box-shadow`, so keyboard focus was invisible and surfaces were indistinguishable from the page. Both now use `outline`, which survives the mode and adds no layout box. `e2e/contrast-modes.spec.ts` pins all of it, since the only way to know what survives is to render it.
- `prefers-contrast: less` is not implemented, and that is a decision rather than an omission: no major platform surfaces a control that sets it.
